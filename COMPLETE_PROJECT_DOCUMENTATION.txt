1. PROJECT OVERVIEW
================================================================================

PROJECT NAME: HireSmart - AI Resume Screening System

DESCRIPTION:
HireSmart is an intelligent resume screening platform that automates candidate 
evaluation for recruiters and hiring managers. It uses Natural Language 
Processing (NLP), machine learning techniques, and OpenAI GPT integration to 
match resumes against job descriptions, score candidates, and provide 
actionable insights.

KEY FEATURES:
- User authentication and role-based access
- Resume upload (PDF, DOCX, TXT formats)
- Job description input and parsing
- AI-powered resume analysis and scoring
- OpenAI GPT-3.5 as primary scoring engine (NEW)
- Traditional TF-IDF NLP as intelligent fallback
- Candidate ranking and classification
- Interactive dashboard with analytics
- Analysis history tracking
- Batch processing support
- Detailed candidate insights and recommendations

TECHNOLOGY STACK:
Frontend:  React 18.2 + Vite 5.0
Backend:   Node.js + Express 4.18
AI/NLP:    Python 3.8+ (scikit-learn, NLTK, OpenAI)
Database:  MongoDB 7.0 (with JSON fallback)
Queue:     Redis + Bull 3.16 (with in-memory fallback)
Deploy:    Docker + Docker Compose

8. AUTHENTICATION & SECURITY
================================================================================

AUTHENTICATION SYSTEM:

Strategy: JWT (JSON Web Tokens) with Refresh Tokens

Token Types:

1. Access Token
   - Duration: 15 minutes
   - Purpose: API authentication
   - Storage: Memory (frontend)
   - Transmission: Authorization header
   - Format: Bearer <token>

2. Refresh Token
   - Duration: 7 days
   - Purpose: Get new access tokens
   - Storage: HTTP-only cookie (secure in prod)
   - Transmission: Cookie or request body
   - Rotation: New token on each refresh

Flow:

1. Login:
   User → POST /api/auth/login
   Backend verifies password
   Backend generates access + refresh tokens
   Frontend stores tokens

2. Authenticated Request:
   Frontend → API with Authorization: Bearer <access_token>
   Backend validates token
   Backend extracts user from token
   Request proceeds if valid

3. Token Expiry:
   Access token expires (15 min)
   Frontend interceptor catches 401
   Frontend calls /api/auth/refresh with refresh token
   Backend validates refresh token
   Backend issues new access token
   Frontend retries original request

4. Logout:
   Frontend → POST /api/auth/logout
   Backend invalidates refresh token
   Frontend clears tokens

SECURITY MEASURES:

1. Password Security
   - bcrypt hashing (10 rounds)
   - Salt per password
   - Never stored plain text
   - Minimum requirements enforced

2. Token Security
   - Secret key from environment
   - Signed tokens (prevents tampering)
   - Short expiration times
   - Refresh token rotation

3. HTTP Security Headers (Helmet)
   - X-Content-Type-Options: nosniff
   - X-Frame-Options: DENY
   - X-XSS-Protection: 1; mode=block
   - Strict-Transport-Security (HTTPS)
   - Content-Security-Policy

4. Input Validation (Joi)
   - Type checking
   - Format validation
   - Length limits
   - Sanitization

5. CORS Configuration
   - Allowed origins whitelist
   - Credentials support
   - Preflight handling

6. Rate Limiting
   - Login attempts: 5 per 15 minutes
   - API requests: 100 per 15 minutes
   - File uploads: 10 per hour

7. File Upload Security
   - Type validation (PDF, DOCX, TXT only)
   - Size limits (10MB per file, 50MB total)
   - Virus scanning (optional)
   - Content inspection

8. SQL Injection Prevention
   - Mongoose ODM (parameterized queries)
   - No raw query execution

9. XSS Prevention
   - Input sanitization
   - Output encoding
   - CSP headers

10. CSRF Protection
    - Token validation
    - SameSite cookies

   Library: pdf-parse
   Process:
     - Read file buffer
     - Extract text content
     - Handle multi-page PDFs
     - Preserve formatting
   Limitations:
     - Image-based PDFs (scanned) may fail
     - Tables extracted as plain text

2. DOCX (.docx)
   Library: mammoth
   Process:
     - Unzip DOCX archive
     - Parse XML structure
     - Extract paragraphs
     - Handle images (optional)
   Limitations:
     - Complex formatting may be lost
     - Embedded objects skipped

3. TXT (.txt)
   Library: fs (Node.js built-in)
   Process:
     - Direct file read
     - UTF-8 encoding
     - No parsing needed
   Limitations:
     - No formatting information
     - Plain text only

ERROR HANDLING:

- Corrupt files: Caught and logged
- Unsupported formats: Rejected at upload
- Empty files: Validation error
- Parsing failures: Resume skipped, others continue

17. SYSTEM WORKFLOWS
================================================================================

WORKFLOW 1: USER REGISTRATION AND LOGIN

Step 1: User Registration
  1. User visits /register page
  2. Fills form (email, password, name, role)
  3. Submit → POST /api/auth/register
  4. Backend validates with Joi
  5. Backend hashes password with bcrypt
  6. Backend creates User in MongoDB
  7. Backend generates JWT tokens
  8. Frontend stores tokens
  9. Redirect to /dashboard

Step 2: User Login (Subsequent)
  1. User visits /login page
  2. Enters email and password
  3. Submit → POST /api/auth/login
  4. Backend finds user by email
  5. Backend compares password hashes
  6. Backend updates lastLogin
  7. Backend generates new tokens
  8. Frontend stores tokens
  9. Redirect to /dashboard

WORKFLOW 2: RESUME ANALYSIS (BATCH)

Step 1: Upload Job Description and Resumes
  1. User navigates to /analyze page
  2. Enters job title and description
  3. Drags/drops multiple PDF/DOCX/TXT files
  4. React Dropzone validates file types and sizes
  5. Click "Analyze" button

Step 2: File Submission
  6. Frontend creates FormData object
  7. Appends jobTitle, jobDescription, resume files
  8. axios POST to /api/analyze/batch (multipart)
  9. Includes Authorization header with JWT

Step 3: Backend Processing
  10. Express receives request
  11. auth middleware validates JWT
  12. Multer middleware saves files to disk
  13. Controller extracts job and resume data
  14. For each resume:
      a. resumeParser extracts text (PDF/DOCX/TXT)
      b. Text stored temporarily
  15. Create Analysis record in MongoDB (pending)
  16. Queue batch job with Bull (or process directly)
  17. Return analysisId to frontend

Step 4: Queue Processing (NEW: OpenAI-First)
  18. Bull worker picks up job
  19. For each resume:
      a. TRY: Call openai_analyzer.score_resume_with_gpt()
         - Send job description + resume to GPT-3.5
         - GPT analyzes semantically
         - Returns: score, classification, skills, reasoning
         - Mark as "openai_gpt" engine
      b. IF OpenAI FAILS/UNAVAILABLE:
         - FALLBACK: Use traditional NLP (resume_match.py)
         - TF-IDF vectorization
         - Cosine similarity
         - Dictionary skill matching
         - Mark as "traditional_nlp" engine
      c. Store result with engine metadata
  20. Aggregate all results
  21. Calculate statistics
  22. Update Analysis record in MongoDB

Step 5: Results Display
  23. Backend marks job as completed
  24. Frontend polls /api/analyze/results/:id
  25. Receives ranked candidate list
  26. Displays results on /results/:id page
  27. Shows: scores, classifications, skills, reasoning
  28. Indicates: which engine was used (GPT or NLP)

WORKFLOW 3: VIEWING HISTORY

Step 1: View Past Analyses
  1. User navigates to /history page
  2. Frontend → GET /api/analyze/history
  3. Backend queries MongoDB for user's analyses
  4. Returns paginated list
  5. Frontend displays table

Step 2: View Specific Analysis
  6. User clicks "View Details"
  7. Navigate to /results/:analysisId
  8. Same as Workflow 2, Step 5

WORKFLOW 4: TOKEN REFRESH (Automatic)

Step 1: Access Token Expires
  1. User makes API request (e.g., GET /api/analyze/history)
  2. Access token expired (15 min passed)
  3. Backend returns 401 Unauthorized

Step 2: Automatic Refresh
  4. Axios interceptor catches 401 error
  5. Frontend → POST /api/auth/refresh with refresh token
  6. Backend validates refresh token
  7. Backend issues new access token
  8. Backend rotates refresh token
  9. Frontend stores new tokens

Step 3: Retry Original Request
  10. Frontend retries original request with new token
  11. Request succeeds
  12. User experiences no interruption

WORKFLOW 5: OPENAI SCORING (NEW)

Primary Path (OpenAI Available):
  1. Resume text + Job description prepared
  2. Call OpenAIAnalyzer.is_enabled() → True
  3. Call score_resume_with_gpt()
  4. Construct GPT prompt with job requirements
  5. Call OpenAI API (gpt-3.5-turbo)
  6. GPT returns JSON analysis:
     - overall_score (0-100)
     - classification tier
     - matched_skills array
     - missing_skills array
     - experience_match level
     - summary and reasoning
     - key strengths/weaknesses
  7. Parse and normalize response
  8. Add "scoring_engine": "openai_gpt"
  9. Return to caller

Fallback Path (OpenAI Unavailable):
  1. OpenAI initialization fails or API call errors
  2. Catch exception
  3. Log: "Falling back to traditional NLP"
  4. Call ResumeAnalyzer.analyze_resume()
  5. TF-IDF vectorization of texts
  6. Cosine similarity calculation
  7. Skill dictionary matching
  8. Experience regex parsing
  9. Scoring formula (70% skills, 30% experience)
  10. Classification by thresholds
  11. Add "scoring_engine": "traditional_nlp"
  12. Return to caller

ALGORITHM 1: OPENAI GPT SCORING (NEW - PRIMARY)

Input:
  - job_title: string
  - job_description: string
  - resume_text: string
  - candidate_name: string

Process:
  1. Initialize OpenAI client with API key
  2. Construct comprehensive GPT prompt:
     {
       "system": "You are an expert HR recruiter",
       "user": "Analyze resume against job requirements..."
     }
  3. Call OpenAI API:
     - Model: gpt-3.5-turbo
     - Temperature: 0.3 (consistent but creative)
     - Max tokens: 1200
  4. GPT performs:
     - Semantic understanding of job requirements
     - Contextual matching of candidate experience
     - Skill extraction with synonym awareness
     - Experience level assessment
     - Must-have skills verification
     - Cultural fit indicators
  5. GPT returns JSON:
     {
       "overall_score": 85,
       "classification": "Suitable",
       "matched_skills": [...],
       "missing_skills": [...],
       "experience_match": "Senior",
       "reason_for_score": "...",
       "key_strengths": [...],
       "key_weaknesses": [...],
       "must_have_skills_found": true
     }
  6. Normalize and validate response
  7. Add metadata: "scoring_engine": "openai_gpt"

Output:
  {
    "score": 85,
    "classification": "Suitable",
    "matched_skills": [...],
    "missing_skills": [...],
    "experience_match": "Senior",
    "summary": "...",
    "detailed_explanation": {...},
    "scoring_engine": "openai_gpt"
  }

Advantages:
  - Understands "React" and "React.js" are the same
  - Knows "Go" programming language vs "Go" verb
  - Considers industry context (fintech vs gaming)
  - Recognizes transferable skills
  - Provides reasoning and explanations

Limitations:
  - Requires API key ($0.0015/resume cost)
  - Needs internet connection
  - 2-5 second latency per resume
  - Subject to API rate limits


ALGORITHM 2: TRADITIONAL TF-IDF NLP (FALLBACK)

Input:
  - job_title: string
  - job_description: string
  - resume_text: string
  - candidate_name: string

Process:

  STEP 1: Text Preprocessing
    1.1. Convert to lowercase
    1.2. Remove special characters
    1.3. Tokenize text (split into words)
    1.4. Remove stopwords (the, is, at, etc.)
    1.5. Lemmatize words (running → run)

  STEP 2: Skill Extraction
    2.1. Load skill dictionary (200+ skills)
    2.2. Scan resume text for skills
    2.3. Scan job description for required skills
    2.4. Matched skills = intersection
    2.5. Missing skills = required - matched

  STEP 3: TF-IDF Vectorization
    3.1. Combine job description and resume text
    3.2. Create TF-IDF vectors:
        TF-IDF = Term Frequency × Inverse Document Frequency
        TF(term) = (# times term appears) / (total terms)
        IDF(term) = log(total docs / docs with term)
    3.3. Generate vector for job description
    3.4. Generate vector for resume

  STEP 4: Semantic Similarity
    4.1. Calculate cosine similarity:
        similarity = (vec1 · vec2) / (||vec1|| × ||vec2||)
        Result: 0.0 (no match) to 1.0 (perfect match)
    4.2. Convert to percentage: similarity × 100

  STEP 5: Experience Level Detection
    5.1. Regex patterns:
        - "10+ years" → Senior
        - "5-7 years" → Mid-level
        - "2-3 years" → Junior
    5.2. Count experience mentions
    5.3. Classify:
        - Executive: 40 points
        - Senior: 35 points
        - Mid-level: 28 points
        - Junior: 18 points
        - Unknown: 10 points

  STEP 6: Skills Matching Score
    6.1. Calculate match percentage:
        skills_match = (matched / required) × 100
    6.2. Convert to score out of 70:
        skills_score = (skills_match / 100) × 70

  STEP 7: Experience Score
    7.1. Convert experience points to 0-30 scale:
        experience_score = (experience_points / 40) × 30

  STEP 8: Overall Score
    8.1. Sum components:
        overall_score = skills_score + experience_score
    8.2. Clamp to 0-100 range
    8.3. Round to 1 decimal place

  STEP 9: Classification
    9.1. Apply thresholds:
        - If all skills matched AND score ≥ 85:
            "Highly Suitable"
        - If score ≥ 70:
            "Suitable"
        - If score ≥ 50:
            "Partially Suitable"
        - If score < 50:
            "Not Suitable"

  STEP 10: Validation Gates
    10.1. Check minimum skill threshold (30%)
    10.2. Check resume substance (>100 words)
    10.3. Check keyword spam (skill repetition)
    10.4. Check relevance (job-resume alignment)
    10.5. If any gate fails: score -= 25

  STEP 11: Generate Explanation
    11.1. Create detailed reasoning
    11.2. List strengths and weaknesses
    11.3. Generate interview questions
    11.4. Create recommendation text

Output:
  {
    "score": 78,
    "classification": "Suitable",
    "matched_skills": ["Python", "AWS", "Docker"],
    "missing_skills": ["Kubernetes", "Go"],
    "experience_match": "Mid-level",
    "skills_match": "85%",
    "qualifications_match": "75%",
    "overall_fit": "78%",
    "summary": "Strong candidate with most required skills...",
    "detailed_explanation": {...},
    "validation": {...},
    "accuracy_metrics": {...},
    "scoring_engine": "traditional_nlp"
  }

Advantages:
  - Always available (no API needed)
  - Free (no per-use cost)
  - Fast (<100ms per resume)
  - Deterministic (same input = same output)
  - Transparent algorithm

Limitations:
  - Exact keyword matching only
  - Misses synonyms ("React" ≠ "React.js")
  - No semantic understanding
  - Can't distinguish context
  - Over-relies on dictionary


SCORING FORMULA (Traditional NLP):

Total Score = Skills Score (70%) + Experience Score (30%)

Skills Score Calculation:
  Raw Match = (Matched Skills / Required Skills) × 100
  Skills Score = (Raw Match / 100) × 70 points

Experience Score Calculation:
  Experience Points:
    Executive: 40 → scales to 30
    Senior: 35 → scales to 26.25

DEPLOYMENT OPTION 1: Local Development

Requirements:
  - Node.js 18+
  - Python 3.8+
  - MongoDB (local or remote)
  - Redis (local or remote)

Steps:
  1. Clone repository
  2. Install backend dependencies:

  3. Install frontend dependencies:
     cd frontend-react && npm install
  4. Install Python packages:
     cd ai && pip install -r requirements.txt
  5. Create .env files with configurations
  6. Start MongoDB and Redis (if local)
  7. Start backend: cd backend && npm start
  8. Start frontend: cd frontend-react && npm run dev
  9. Access at http://localhost:3000

Pros:
  - Full debugging capabilities
  - Fast iteration
  - No Docker needed

Cons:
  - Manual service management
  - Inconsistent environments
  - Dependency hell potential


DEPLOYMENT OPTION 2: Docker Compose (Recommended)

Requirements:
  - Docker 24.0+
  - Docker Compose 2.20+

Steps:
  1. Clone repository
  2. Create .env file in root
  3. Run: docker-compose -f docker-compose.dev.yml up --build
  4. Access at http://localhost:3000

Pros:
  - Consistent environment
  - All services orchestrated
  - Easy teardown (docker-compose down)
  - Close to production

Cons:
  - Docker overhead
  - Slower file updates in dev

Production:
  1. Use docker-compose.prod.yml
  2. Configure production env vars
  3. Run: docker-compose -f docker-compose.prod.yml up -d


DEPLOYMENT OPTION 3: Cloud Platform (AWS Example)

Architecture:
  Frontend: S3 + CloudFront
  Backend: EC2 or ECS (containers)
  Database: MongoDB Atlas or DocumentDB
  Queue: ElastiCache Redis
  Storage: S3 bucket for uploads
  DNS: Route 53
  SSL: Certificate Manager

Steps:
  1. Provision infrastructure:
     - MongoDB cluster
     - Redis cluster
     - S3 buckets
     - EC2 instances or ECS cluster
  2. Build Docker images:
     docker build -t hiresmart-backend backend/
     docker build -t hiresmart-frontend frontend-react/
  3. Push to ECR (Elastic Container Registry)
  4. Deploy to ECS with task definitions
  5. Configure ALB (Application Load Balancer)
  6. Configure CloudFront distribution for frontend
  7. Set up environment variables via Secrets Manager
  8. Configure CI/CD with CodePipeline

Estimated Monthly Cost (Light usage):
  - EC2 t3.medium (backend): $30
  - MongoDB Atlas M10: $57
  - ElastiCache t3.micro: $12
  - S3 storage: $5
  - Data transfer: $10
  - CloudFront: $5
  Total: ~$120/month

Components:
  - Deployments for backend, frontend
