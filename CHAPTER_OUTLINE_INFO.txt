CHAPTER-1
1. INTRODUCTION
======================================================================

The HireSmart system is an AI-assisted resume screening and candidate ranking
platform developed to support modern recruitment teams. Recruitment workflows in
many organizations still depend on manual review of resumes, where recruiters
spend a large amount of time scanning documents, comparing qualifications, and
shortlisting candidates role by role. This manual method is often slow,
inconsistent, and difficult to scale when the number of applicants increases.

HireSmart addresses this challenge through an integrated solution that combines:
- Resume ingestion and text extraction
- Job description analysis
- AI/NLP-based matching logic
- Candidate scoring and classification
- Recruiter dashboard analytics
- Shortlisting support and report export

The project is structured as a full-stack application with frontend, backend,
and scoring services, with optional support for Python/OpenAI-based analysis
pipelines and robust fallback behavior when optional AI dependencies are not
available.

The central objective is not only to produce a score, but to provide explainable
and actionable outputs, such as matched skills, missing skills, role fit,
recommendation level, and shortlist guidance.


1.1 PURPOSE OF THE PROJECT

The purpose of this project is to design and implement an intelligent and
practical hiring assistant for recruiters, HR teams, and technical interview
coordinators. The system is intended to improve speed, consistency, and quality
of initial resume screening decisions.

Primary goals:
1. Reduce manual screening effort by automating first-level candidate evaluation.
2. Improve relevance of shortlisted candidates using contextual role matching.
3. Provide transparent and explainable outputs for every decision.
4. Support recruiter productivity with dashboard metrics and reusable history.
5. Enable scalable screening through API-first modular architecture.

Operational goals:
- Handle multiple resumes per role with stable processing behavior.
- Support common resume file types and varying document quality.
- Return easy-to-understand classification labels:
  Suitable / Partially Suitable / Not Suitable.
- Provide downloadable reports for audit, communication, and documentation.

Academic and practical goals:
- Demonstrate software engineering lifecycle from SRS to testing.
- Apply AI/NLP concepts in a real-world use case.
- Build a project suitable for college evaluation and practical deployment.


1.2 PROBLEM WITH EXISTING SYSTEMS

Existing resume screening approaches often suffer from one or more of the
following limitations:

A. Manual Screening Problems
- Recruiters read resumes one by one.
- High time consumption for each vacancy.
- Inconsistent judgment across different reviewers.
- Difficult to maintain objective comparison among candidates.

B. Basic Keyword Filtering Problems
- Plain keyword matching fails to understand context.
- Good candidates may be missed due to wording variations.
- Profiles with repeated buzzwords may appear stronger than they are.
- No clear explanation of why a candidate is selected or rejected.

C. Scalability and Reliability Problems
- Traditional process slows down as volume increases.
- Repeated data entry and report generation overhead.
- Limited analytics for long-term hiring improvement.
- Inability to compare role-specific skill fit in a structured way.

D. Decision Transparency Problems
- Recruiters and managers need explainable reasons for shortlist decisions.
- Existing simple systems do not provide meaningful breakdowns.
- Difficult to justify selection in formal review environments.

HireSmart is proposed specifically to address these limitations through
structured, explainable, and repeatable analysis.


1.3 PROPOSED SYSTEM

The proposed system is a hybrid AI-assisted architecture that combines rule-based
and intelligent scoring approaches to deliver reliable results in different
runtime environments.

Main capabilities:
1. Secure user authentication for recruiter access.
2. Resume upload and text extraction from supported file formats.
3. Job title + job description contextual analysis.
4. Skill coverage computation (matched and missing skills).
5. Experience and qualification-aware scoring.
6. Classification and recommendation generation.
7. Candidate shortlist support with export-ready output.
8. Dashboard visibility for analysis history and usage patterns.

Design philosophy:
- Practical first: must work reliably even when optional AI integrations fail.
- Explainability first: every score should be accompanied by reasons.
- Modular first: frontend, backend, and scoring logic are separable.
- Scalable first: API endpoints and queue-ready architecture for future growth.

The system outputs include:
- Numerical match score
- Suitability class
- Matched skills and missing skills
- Experience fit
- Summary and recommendation
- Data for shortlist and report generation

The architecture follows a layered flow where each component has clear

High-level architecture (text diagram):

CHAPTER-2
2. LITERATURE SURVEY
======================================================================

Resume screening automation has evolved from manual checklists and keyword
filters to hybrid AI models that combine statistical, semantic, and domain-aware
scoring.

2.1 Existing Approaches Studied

A. Manual HR Screening Frameworks
- Strength: Human judgment on communication and domain context.
- Weakness: Very slow for high-volume hiring; inconsistent outcomes.

B. Keyword-Based ATS Filters
- Strength: Fast initial filtering.
- Weakness: Low contextual intelligence and high false negatives.

C. Rule-Based Matching Systems
- Strength: Deterministic and explainable.
- Weakness: Hard to maintain for changing skill taxonomies.

D. ML/NLP Resume Matching Systems
- Strength: Better semantic understanding and ranking quality.
- Weakness: Requires data quality, model monitoring, and explainability layer.

E. Hybrid AI + Heuristic Systems
- Strength: Better production reliability with explainable fallback behavior.
- Weakness: Additional architecture complexity.

2.2 Key Findings from Literature

1. Contextual matching outperforms static keyword counting for role fit.
2. Explainability is necessary for recruiter trust and adoption.
3. Hybrid architectures are more practical in real deployment environments.
4. Resume parsing quality significantly affects final match reliability.
5. Weighted scoring allows customization for role-specific priorities.

2.3 Gap Identified

Many available systems either:
- Prioritize speed with weak explainability, or
- Prioritize complexity with fragile runtime dependencies.

The identified need is a balanced system that is:
- Intelligent yet reliable,
- Explainable yet efficient,
- Modular and deployable in constrained environments.

2.4 Survey-Driven Design Decisions in HireSmart

Based on literature observations, HireSmart adopts:
- Hybrid scoring approach
- Detailed matched/missing skill outputs
- Practical fallback behavior
- Recruiter-focused UI with direct shortlist actions
- Testable API-first design

4.1 INTRODUCTION TO UML

UML (Unified Modeling Language) is used to represent the structural and
behavioral aspects of HireSmart before and during implementation. UML improves
communication among developers, reviewers, and evaluators by presenting system
logic in standardized visual/behavioral form.

Benefits in this project:
- Clarifies user interactions and workflows.
- Validates process sequence before coding.
- Identifies states and transition rules in analysis lifecycle.
- Documents deployment and environment boundaries.


4.2 UML DIAGRAMS

4.2.1 USE CASE DIAGRAM

Actors:
- Recruiter/User
- System Admin (optional)

Primary Use Cases:
1. Register account
2. Login
3. Upload resume(s)
4. Enter job details
5. Start analysis
6. View candidate ranking
7. View matched and missing skills
8. Add candidate to shortlist
9. Export report
10. View dashboard and history

Use Case Relationships:
- Login is required before protected actions.
- Analyze includes validation and scoring sub-processes.
- Shortlist action depends on completed analysis.
- Export depends on available analysis/shortlist data.


4.2.2 SEQUENCE DIAGRAM

Main sequence:
1. User submits job data + resume files.
2. Frontend sends request to backend API.
3. Backend validates token and inputs.
4. Backend parses file contents.
5. Backend invokes scoring service.
6. Scoring service returns structured analysis.
7. Backend stores result in DB.
8. Backend responds with normalized payload.
9. Frontend renders result cards and actions.

Alternative sequence (fallback path):
- If advanced AI module unavailable, backend runs fallback scoring engine and
  still returns complete response structure.

Error sequence:
- Invalid input -> validation error response.
- Unsupported file -> upload error response.
- Token expired -> authentication error response.


4.2.3 STATE CHART DIAGRAM

Analysis state lifecycle:
- Idle
- InputValidated
- Queued (optional)
- Processing
- Completed
- Failed

Transitions:
- Idle -> InputValidated when request passes checks.
- InputValidated -> Processing or Queued.
- Processing -> Completed on success.
- Processing -> Failed on parsing/scoring failure.
- Failed -> Idle on user retry.

State persistence:
- Timestamps and status markers recorded for traceability.


4.2.4 DEPLOYMENT DIAGRAM

Nodes:
1. Client Node
   - Browser with frontend app
2. Application Node
   - Node.js/Express backend
3. AI Node (optional or integrated)
   - Python services / AI integration runtime
4. Database Node
   - MongoDB instance
5. Queue Node (optional)
   - Redis + worker process

Deployment topologies:
- Local academic setup: single machine multi-process.
- Lightweight edge setup: Raspberry Pi + remote DB.
- Cloud-ready setup: containerized multi-service deployment.

Security boundary:
- API endpoints protected by auth middleware.
- Database access controlled by connection credentials.
