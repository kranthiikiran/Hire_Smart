PROJECT OVERVIEW
================================================================================
HireSmart is a production-ready, AI-powered resume screening system designed to 
automate candidate evaluation using Natural Language Processing (NLP) and machine 
learning. It helps recruiters save time by automatically analyzing resumes against 
job descriptions, ranking candidates, and providing detailed insights.

TARGET USERS:
  • Recruiters: Batch upload and analyze multiple resumes
  • Job Seekers: Get AI-powered feedback on resumes
  • HR Professionals: Generate job descriptions and match candidates

PHASE 5: SEMANTIC MATCHING & SIMILARITY ANALYSIS
================================================================================
Step 5.1: Extract Job Requirements as Keywords
  Data Input: Job description provided by user
  Technologies Used:
    • Python: ai/resume_match.py
    • scikit-learn 1.x - TF-IDF vectorization
    • sklearn.feature_extraction.text.TfidfVectorizer
  
  Process:
    1. Job description tokenized into keywords
    2. Common stop words removed (the, a, an, etc.)
    3. Remaining words weighted by importance
    4. TF-IDF scores calculated for each keyword
  
  Example Job Requirements:
    Input: "We need a Senior React Developer with 5+ years experience, 
            proficient in Node.js, PostgreSQL, Docker, and AWS"
    
    Extracted Keywords:
    {
      "React": 0.95 (high importance),
      "Senior": 0.85,
      "Node.js": 0.92,
      "PostgreSQL": 0.88,
      "Docker": 0.87,
      "AWS": 0.86,
      "experience": 0.60
    }

Step 5.2: Calculate Semantic Similarity
  Backend Service: ai/resume_match.py
  Technologies Used:
    • scikit-learn - Cosine Similarity
    • sklearn.metrics.pairwise.cosine_similarity
    • NumPy - Matrix operations
  
  Algorithm:
    1. Resume text converted to TF-IDF vector
    2. Job description converted to TF-IDF vector
    3. Cosine similarity calculated: CS = (A·B) / (||A|| × ||B||)
       Where: A = resume vector, B = job vector
    4. Result: similarity_score between 0 and 1
  
  Example Calculation:
    Resume Vector TF-IDF:
    [React=0.82, Node.js=0.78, PostgreSQL=0.71, Docker=0.65, AWS=0.60]
    
    Job Vector TF-IDF:
    [React=0.95, Node.js=0.92, PostgreSQL=0.88, Docker=0.87, AWS=0.86]
    
    Cosine Similarity = 0.92 (92% match)

PHASE 6: SCORING & RANKING
================================================================================
Step 6.1: Calculate Composite Match Score
  Backend Service: services/aiService.js
  Technologies Used:
    • Custom scoring algorithm (Node.js)
    • Python inter-process calls
  
  Weighted Scoring Formula:
  
  FINAL_SCORE = (SkillMatch × 0.60) + (ExperienceRelevance × 0.25) + (SemanticSimilarity × 0.15)
  
  Where:
    • SkillMatch (60% weight):
      - Count matching skills from database
      - Formula: (Matched Skills / Total Required Skills) × 100
      - Example: 8 matched / 10 required = 80%
    
    • ExperienceRelevance (25% weight):
      - Years of experience extraction from resume
      - Level matching (Entry/Mid/Senior)
      - Formula: (Years Extracted / Years Required) × 100 (capped at 100%)
      - Example: 6 years provided / 5 years required = 100%
    
    • SemanticSimilarity (15% weight):
      - Cosine similarity from previous step
      - Formula: cosine_similarity_score × 100
      - Example: 0.92 × 100 = 92%
  
  Example Calculation:
    Resume: John Doe
      • Matched Skills: 8/10 = 80%
      • Experience: 6 years (required 5) = 100%
      • Semantic Similarity: 0.92 = 92%
    
    FINAL_SCORE = (80 × 0.60) + (100 × 0.25) + (92 × 0.15)
                = 48 + 25 + 13.8
                = 86.8 (87% overall match)

Step 6.2: Candidate Classification
  Backend Logic: services/aiService.js
  
  Classification Rules:
    • SUITABLE (✓): Score >= 75%
      → Highly recommended for interview
      → Strong skill match and experience alignment
    
    • PARTIALLY_SUITABLE (⚠): Score 50-75%
      → Consider for further review
      → Good potential with some skill gaps
    
    • NOT_SUITABLE (✗): Score < 50%
      → Limited match with position
      → May need significant training
  
  Storage Format:
    {
      "resume_id": "uuid-hash",
      "candidate_name": "John Doe",
      "email": "john.doe@email.com",
      "match_score": 87,
      "classification": "SUITABLE",
      "skill_match": 80,
      "experience_match": 100,
      "semantic_match": 92,
      "matched_skills": ["React", "Node.js", "PostgreSQL", "Docker", "AWS"],
      "missing_skills": ["Kubernetes", "GraphQL"],
      "additional_skills": ["Java", "Python"],

PHASE 7: BATCH PROCESSING OPTIMIZATION
================================================================================
Step 7.1: Handle Multiple Resumes (Batch)
  Backend Service: services/batchProcessor.js
  Technologies Used:
    • Bull 3.16.0 - Job queue management
    • Redis 4.6.8 - Queue backend (optional)
    • Async/Await - Concurrent processing
    • Node.js Worker Threads (optional)
  
  Maximum Batch Size: 20 resumes
  Processing Strategy:
    1. Queue system receives batch upload
    2. Job split into 4 concurrent workers
    3. Each worker processes 5 resumes simultaneously
    4. Progress tracking for frontend
    5. Results aggregated and returned
  
  Performance Optimization:
    • Caching: Processed job descriptions stored in memory
    • Reuse: Prevents re-processing same job description
    • Concurrency: Multiple Python processes spawn in parallel
    • Queue Management: Failed jobs automatically retry (3 attempts)
  
  Queue Entry Structure:
    {
      "job_id": "batch-uuid",
      "resumes": [
        { "path": "uploads/hash1.pdf", "original_name": "resume1.pdf" },
        { "path": "uploads/hash2.txt", "original_name": "resume2.txt" }
      ],
      "job_description": "...",
      "user_id": "user-uuid",
      "created_at": "2026-03-06T10:30:45Z",
      "status": "processing"
    }

Step 7.2: Aggregate & Sort Results
  Backend Process: Collect results from all workers
  
  Sorting Algorithm:
    1. All results collected in array
    2. Sort by match_score (descending)
    3. Add ranking: rank_1, rank_2, rank_3, etc.
    4. Group by classification (SUITABLE first)

PHASE 11: SECURITY & AUTHENTICATION
================================================================================
Step 11.1: JWT Token Management
  Technologies Used:
    • jsonwebtoken 9.0.2 - Token creation/verification
    • Middleware: middleware/auth.js
    • Express middleware chain
  
  Token Flow:
    1. User logs in successfully
    2. Server generates JWT token:
       Header: { "alg": "HS256", "typ": "JWT" }
       Payload: {
         "user_id": "uuid",
         "email": "user@email.com",
         "role": "recruiter",
         "iat": 1709756445,
         "exp": 1709760045
       }
       Signature: HMAC-SHA256(header.payload, SECRET_KEY)
    
    3. Token sent to frontend
    4. Frontend stores in localStorage
    5. Token included in every API request:
       Headers: { "Authorization": "Bearer token..." }
    6. Backend middleware verifies token signature
    7. If valid, request processed; if invalid, 401 Unauthorized

Step 11.2: Password Security
  Technologies Used:
    • bcryptjs 2.4.3 - Password hashing
    • Salt rounds: 10 (industry standard)
  
  Password Handling:
    1. User registration: password received
    2. Generate salt: bcrypt.genSalt(10)
    3. Hash password: bcrypt.hash(password, salt)
    4. Store hash in database
    5. Never store plain text
    6. Login: bcrypt.compare(provided, stored_hash)

Step 11.3: Input Validation
  Backend Middleware: middleware/validation.js
  Technologies Used:
    • Joi 17.11.0 - Schema validation
    • Validator 13.11.0 - Utility validators
  
  Validation Rules:
    1. Email validation:
       Schema: Joi.string().email().required()
       Pattern: RFC 5322 compliant
    
    2. Password validation:
       Minimum 8 characters
       At least 1 uppercase
       At least 1 lowercase
       At least 1 number
       At least 1 special character
    
    3. Resume file validation:
       Allowed MIME: application/pdf, application/msword, text/plain
       Maximum size: 5 MB
       Magic number check (file signature)
    
    4. Job description validation:
       Minimum 50 characters
       Maximum 5000 characters
       No SQL injection patterns
       No script tags

Step 11.4: Security Headers
  Backend Middleware: Helmet 7.0.0
  
  Headers Applied:

================================================================================
                            SCALABILITY CONSIDERATIONS
================================================================================

Current Architecture Limitations:
  • File-based storage (JSON) not suitable for >10,000 analyses
  • Single-threaded Python analysis (bottleneck)
  • In-memory cache limited by RAM (development)
  • No horizontal scaling in current setup

Scaling Solutions:

  1. Database Migration:
     JSON → PostgreSQL with full-text search
     Benefit: Unlimited storage, better querying

  2. Job Queue Enhancement:
     Current: Bull in-memory
     Scaled: Redis-backed Bull + multiple workers
     Benefit: Distributed processing, automatic retry

  3. Microservices:
     • API Service (Node.js)
     • AI Service (Python + FastAPI)
     • Storage Service (Database)
     • Cache Service (Redis)
     Benefit: Independent scaling of each component

  4. Horizontal Scaling:
     • Load Balancer (nginx, HAProxy)
     • Multiple backend instances
     • Shared database/cache layer
     Benefit: Handle 10x-100x more users

================================================================================
                            TROUBLESHOOTING GUIDE
================================================================================

Common Issues & Solutions:

1. PDF Text Extraction Fails:
   Cause: Scanned PDF without OCR
   Solution: Use OCR library (Tesseract) or warn user
   Technologies: pdf-parse + Tesseract

2. High Memory Usage:
   Cause: Large batch processing
   Solution: Implement streaming, increase worker memory
   Technologies: Bull memory optimization, worker threads

3. Slow Analysis:
   Cause: No caching, repeated processing
   Solution: Implement Redis caching
   Technologies: Redis + cacheManager optimization

4. Authentication Errors:
   Cause: JWT token expiry
   Solution: Implement refresh token rotation
   Technologies: JWT refresh token endpoint

5. File Upload Failures:
   Cause: Network timeout, file size
   Solution: Chunked upload, client-side validation
   Technologies: Multer resumable upload
